**MaximML** — full-stack приложение машинного обучения для оценки стоимости жилья в Калифорнии, повторного обучения регрессионных моделей и сбора обратной связи о прогнозах. Проект объединяет REST API на FastAPI, типизированный интерфейс на React, хранение данных в SQLite, запуск через Docker и автоматические проверки качества кода.

Это портфолио-проект, демонстрирующий полный цикл работы с ML-моделью: подготовку данных, обучение, сохранение артефактов, получение прогнозов через API и пользовательский веб-интерфейс.

## Что демонстрирует проект

### Бэкенд и машинное обучение

- REST API на FastAPI с моделями запросов и ответов Pydantic.
- Оценка стоимости жилья на наборе данных California Housing с помощью **Linear Regression** и **Gradient Boosting Regressor**.
- Подготовка данных: фильтрация выбросов, логарифмические преобразования, масштабирование и географические признаки на основе geohash.
- Разделение данных на обучающую и тестовую выборки **до обучения преобразований**, чтобы кодировщик категорий `TargetEncoder` и масштабировщик `StandardScaler` обучались только на обучающих данных.
- Сохранение обученной модели вместе с необходимыми преобразованиями: при прогнозировании используются параметры, полученные на этапе обучения, без повторного `fit` на одном входном объекте.
- Загрузка набора данных California Housing при запросе на обучение; запуск API исключительно для прогнозирования не требует его предварительного скачивания.
- SQLAlchemy 2.0 для истории обучения и сохранения обратной связи о прогнозах.
- Логирование приложения и эндпоинт проверки работоспособности.

### Фронтенд

- Одностраничное приложение на React и TypeScript с типизированными API-клиентами на Axios.
- Форма ввода характеристик жилья, выбор модели и отображение рассчитанной стоимости.
- Запуск обучения моделей из интерфейса и просмотр истории обучения.
- Обработка состояний загрузки, успешных и неуспешных запросов.

### Развёртывание и качество кода

- Docker Compose для запуска FastAPI, React-приложения и Nginx; отдельные Docker-тома для SQLite и файлов моделей.
- GitHub Actions для проверки бэкенда и фронтенда, запуска тестов, сборки React и Docker-образов.
- Работа с ветками `main`, `develop` и `feature/*` через Pull Request.

```text
        │
        ▼

                         ▼

```

Фронтенд отвечает за ввод параметров и отображение результатов. Подготовка датасета, генерация признаков, обучение, прогнозирование и запись истории выполняются на стороне бэкенда.

## Основные технические решения

- **ML-логика на сервере.** Браузер отправляет параметры жилья и команды, а API отвечает за обучение, инференс и работу с файлами моделей.
- **Общие преобразования при обучении и прогнозировании.** Сохранённый артефакт включает обученный конвейер обработки признаков и регрессионную модель. Это предотвращает расхождение между подготовкой данных на этапе обучения и при последующих прогнозах.
- **Изоляция тестовой выборки.** `TargetEncoder` и `StandardScaler` обучаются только на обучающей выборке. При прогнозировании преобразования не переобучаются.
- **История обучения.** Успешные и неуспешные попытки обучения записываются в SQLite. Для успешных запусков сохраняются метрики `R²` и `MSE`.
- **Отдельное хранение данных и моделей.** Docker-тома сохраняют SQLite и артефакты моделей при пересоздании контейнеров.
- **Типизированные интерфейсы между слоями.** Pydantic, TypeScript и модели SQLAlchemy помогают фиксировать структуру передаваемых данных.

## Жизненный цикл ML-модели

```text
Запрос на обучение
        │
        ▼
California Housing + отмеченная как корректная обратная связь
        │
        ▼
Фильтрация выбросов → разделение на train / test
        │                     │
        │                     └── Оценка R² и MSE на тестовой выборке
        ▼
Обучение конвейера на train
    ├── Логарифмические и географические признаки
    ├── TargetEncoder
    ├── StandardScaler
    └── Регрессионная модель
        │
        ▼
Сохранение обученного артефакта модели

Запрос прогноза
        │
        ▼
Pydantic → обученные преобразования → predict() → оценка стоимости
```

Для градиентного бустинга дополнительно используется подбор гиперпараметров с помощью `RandomizedSearchCV`. Кодировщик и масштабировщик не переобучаются во время запроса прогнозирования.

Обратная связь с флагом корректности может добавляться к данным при следующем обучении. Флаг выставляется пользователем; он сам по себе не подтверждает точность оценки независимо от пользователя.

## Запуск приложения

### Docker — рекомендуемый способ

**Требования:** Docker Engine или Docker Desktop и Docker Compose.

```bash
git clone https://github.com/DanilFaritovich/maxim-ml.git
cd maxim-ml
docker compose up --build
```

Открой приложение в браузере:

```text
http://127.0.0.1:8080
```

Nginx раздаёт сборку React и проксирует запросы на прогнозирование, обучение, обратную связь и документацию FastAPI к контейнеру бэкенда.

Данные SQLite и артефакты моделей сохраняются в именованных Docker-томах даже после пересоздания контейнеров.

Чтобы пересобрать и пересоздать запущенное локальное приложение:

```bash
docker compose up --detach --build --force-recreate
```

Если изменился формат сохраняемых моделей, повторно обучи обе модели через интерфейс или запросы `POST /train/{model_name}`, чтобы получить совместимые артефакты.

**Внимание:** команда ниже удалит тома приложения вместе с локальной базой данных, историей и сохранёнными моделями. Используй её только для демонстрационного окружения, данные которого не нужно сохранять:

```bash
docker compose down -v
```

## Запуск для разработки

### Бэкенд

**Требование:** Python 3.12.

Из корня репозитория:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
uvicorn main:app --reload
```

На Windows активируй виртуальное окружение командой `.venv\Scripts\activate` вместо `source`.

Адрес API: `http://127.0.0.1:8000`.

Интерактивная документация FastAPI: `http://127.0.0.1:8000/docs`.

### Фронтенд

**Требования:** Node.js 20 и npm.

В отдельном терминале из корня репозитория:

```bash
cd react-app
npm ci
npm start
```

Локальный сервер React обычно запускается по адресу `http://localhost:3000`. Бэкенд разрешает запросы от локального React-приложения через CORS.

## Работа с приложением

1. Перейди в раздел обучения и выбери модель `linear_regression` или `gradient_boosting_regressor`.
2. Запусти обучение и проверь результат в истории запусков.
3. Открой раздел прогнозирования, выбери модель и введи характеристики жилья.
4. Получи оценку стоимости и при необходимости отправь обратную связь.

Прогнозы предназначены для демонстрации работы ML-сервиса на наборе данных California Housing, а не для профессиональной оценки недвижимости.

## Обзор API

| Метод | Эндпоинт | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Проверка работоспособности сервиса |
| `POST` | `/predict/{model_name}` | Прогноз стоимости жилья |
| `POST` | `/train/{model_name}` | Обучение и сохранение модели |
| `GET` | `/train/history` | История обучения моделей |
| `POST` | `/train_feedback/feedback` | Сохранение отзыва о прогнозе |

Поддерживаемые имена моделей: `linear_regression` и `gradient_boosting_regressor`.

### Входные характеристики для прогнозирования

API принимает восемь числовых полей, соответствующих признакам California Housing:

| Поле | Значение |
| --- | --- |
| `MedInc` | Медианный доход в районе |
| `HouseAge` | Медианный возраст домов |
| `AveRooms` | Среднее количество комнат |
| `AveBedrms` | Среднее количество спален |
| `Population` | Население района |
| `AveOccup` | Среднее число проживающих на домохозяйство |
| `Latitude` | Широта |
| `Longitude` | Долгота |

Для проверки API также доступна документация OpenAPI по адресу `/docs`.

## Работа с ветками

1. Создай ветку `feature/...` или `fix/...` от `develop`.
2. Сделай изменения и открой Pull Request в `develop`.
3. После успешного CI объедини изменения.
4. Подготовь отдельный Pull Request `develop → main` для релиза.

При переносе изменений между `develop` и `main` обычный merge сохраняет общую историю веток.

## Ограничения текущей версии

- SQLite используется для локальной демонстрации, а не как хранилище многопользовательского промышленного сервиса.
- Модели обучаются на фиксированном демонстрационном наборе данных California Housing и пользовательской обратной связи.
- Файлы моделей также присутствуют непосредственно в репозитории Git; при значительном увеличении размера артефактов можно рассмотреть Git LFS.
- В текущей версии нет отдельных авторизованных рабочих пространств пользователей.
